# نظام إدارة الخدمات الطبية

هذا المشروع هو نسخة عرض تجريبي (MVP) لتطبيق إدارة الخدمات الطبية داخل المنشآت. تم تصميمه ليُظهر كيفية تنظيم العمليات الطبية داخل المؤسسات بطريقة رقمية وسهلة الاستخدام.

## ما هو الهدف من التطبيق؟

التطبيق يساعد في إدارة الطلبات الطبية عبر مراحل واضحة:

- الموظف يقدم طلب كشف طبي ويتابع حالة الطلب.
- إدارة الأقسام تراجع الطلبات وتوافق أو ترفض.
- الأمن يسجل خروج الموظف وعودته بعد الكشف.
- الطبيب يسجل التشخيص ويصدر الروشتة الطبية.
- الصيدلية تصرف الأدوية وتؤكد حالة الطلب.

## لماذا هذا المشروع مهم للعميل؟

- يجعل العمل الطبي المؤسسي أكثر تنظيمًا.
- يقلل الاعتماد على الورق والتنسيق اليدوي.
- يضع كل دور في مكانه الصحيح ضمن النظام.
- يساعد الإدارة على متابعة الأداء واتخاذ القرار بسرعة.
- يمكن تطويره لاحقًا ليعمل مع أنظمة المؤسسة الحقيقية.

## من سيستخدم التطبيق؟

1. الموظف: للوصول لحالته الطبية وطلب الكشف.
2. المدير: للموافقة على الطلبات ومراجعة النتائج.
3. الأمن: لتتبع خروج وعودة الموظفين.
4. الطبيب: لتسجيل التشخيص ووصف العلاج.
5. الصيدلية: لصرف الأدوية ومتابعة الحالات.
6. الإدارة الطبية: لعرض التقارير العامة وسجل النشاط.

## ماذا يقدّم التطبيق الآن؟

- نظام واجهة مستخدم جاهز للعرض.
- صفحات وظيفية لكل دور أساسي.
- تدفقات بيانات داخلية لتوضيح طريقة العمل.
- هيكل يمكن ربطه لاحقًا بأي قاعدة بيانات أو خدمة خارجية.

## البنية التقنية بشكل مبسّط

- تم بناء التطبيق باستخدام **React** و**TypeScript**.
- يعتمد على **Vite** لتشغيل المشروع بسرعة.
- تم استخدام **Tailwind CSS** لتصميم الواجهة بشكل مرن وسريع.
- الانتقال بين الصفحات يتم عبر **React Router**.
- يحتوي على ملفات وبيانات تجريبية توضح حالة كل دور.

## حالة المشروع الحالية

- الواجهة تعمل بشكل تجريبي.
- يمكن فتح النظام وتجريب الأدوار المختلفة.
- البيانات الحالية تستخدم نماذج جاهزة داخل التطبيق.
- يحتاج المشروع إلى ربط بقاعدة بيانات وخدمات حقيقية في المرحلة التالية.

## كيف تشغّل التطبيق

### شروط التشغيل

- تثبيت **Node.js**.
- تثبيت **pnpm**.

### أوامر التشغيل

```bash
cd "d:\Asroc v2\asroc-2-main"
pnpm install

```

بعد تشغيل الأمر الأخير، افتح المتصفح على العنوان المحلي الذي يعرضه Vite.

## ما الذي يمكن عرضه للعميل؟

- عرض واجهة المستخدم وتجربة رحلة الموظف.
- شرح دور كل مستخدم في النظام.
- توضيح كيف يتحول الطلب من مرحلة إلى أخرى.
- عرض إمكانيات التطوير المستقبلية.

## شجرة المشروع بلغة بسيطة

هذا الجزء يوضح بشكل مبسّط أين توجد الأجزاء الرئيسية في المشروع:

```text
asroc-2-main/
├─ src/
│  ├─ app/           # صفحات التطبيق والتنقل بين الشاشات
│  ├─ components/    # عناصر واجهة المستخدم المشتركة مثل الأزرار والقوائم
│  ├─ data/          # بيانات تجريبية تستعمل للعرض بدون قاعدة بيانات
│  ├─ features/      # الوظائف الخاصة بكل دور (إدارة، صيدلية، طبيب، أمن، طلبات)
│  ├─ lib/           # أدوات مساعدة صغيرة داخل التطبيق
│  └─ store/         # المكان الذي يحفظ الحالة الحالية للتطبيق أثناء التشغيل
├─ public/           # ملفات ثابتة يمكن فتحها مباشرة في المتصفح
├─ package.json      # بيانات التشغيل والمكتبات المطلوبة
└─ vite.config.ts    # إعدادات تشغيل المشروع
```

كل مجلد هنا يمثل جزءًا من التطبيق:

- `src/`: يحتوي على التطبيق نفسه.
- `app/`: صفحات النظام الرئيسية وتنقل المستخدم.
- `components/`: عناصر قابلة لإعادة الاستخدام في أي صفحة.
- `data/`: بيانات تجريبية تُستخدم للعرض دون الحاجة لقاعدة بيانات فعلية.
- `features/`: كل نوع من المستخدمين له الجزء الخاص به هنا.
- `store/`: يشبه "الذاكرة" المؤقتة للتطبيق أثناء التشغيل.

## الحالة التقنية الحالية

التطبيق مربوط بـ **Supabase** كقاعدة بيانات حقيقية — المصادقة، الملفات الشخصية، والطلبات كلها مربوطة بـ Supabase مع fallback محلي في بيئة التطوير.

## خطوات التطوير المقبلة

1. تمكين التقارير القابلة للطباعة والتصدير.
2. دعم إشعارات داخلية في الوقت الفعلي (Supabase Realtime).
3. دمج مع أنظمة الموارد البشرية وسجلات الموظفين.
4. تطوير نسخة للشاشات الصغيرة أو الأجهزة اللوحية.
