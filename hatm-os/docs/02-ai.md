# المرحلة ١ (أسبوع ٢–٧) — Name Matching Service

## ليه ده أصعب جزء في المشروع كله

الناس بتكتب أساميها في Zoom بأي شكل:
`أحمد` · `Ahmed M.` · `احمد محمد على` · `Ahmed's iPhone` · `أبو يوسف` ·
`AHMED MOHAMED` · `احمد ✨`

لو المطابقة مش دقيقة، النظام كله بيبقى غير موثوق — لأن كل حاجة بعدها
(الحضور، الرسايل، التقارير) بتقف عليها.

**معيار النجاح:**
```
auto-match rate  ≥ ٩٠٪
false positives  =  صفر
```

⚠️ **مطابقة غلط أخطر بكتير من عدم مطابقة.** لو النظام قال إن "أحمد علي" هو
"أحمد علي حسن" وهو غلط، هيتبعت لواحد رسالة غياب وهو حضر — وده بيكسر الثقة
في النظام كله. لما تشك، **ارجع `needs_review`**.

## الاستراتيجية المتدرجة

بترتيب الثقة — أول واحد بينجح بيوقف السلسلة:

```
١. email مطابق تمامًا          → confidence 1.00  method="email"
٢. alias محفوظ سابقًا            → confidence 1.00  method="alias"
٣. رقم موبايل داخل الاسم        → confidence 0.95  method="phone"
٤. مطابقة نصية بعد التطبيع      → 0.60–0.95       method="fuzzy"
٥. embedding للحالات الغامضة    → 0.50–0.85       method="embedding"
٦. مش متأكد                     → needs_review = true
```

## ١. Normalization Pipeline — الأساس

```python
import re

AR_DIACRITICS = r'[\u064B-\u0652\u0640]'

def normalize_ar(s: str) -> str:
    s = re.sub(AR_DIACRITICS, '', s)                    # تشكيل + تطويل
    s = s.translate(str.maketrans('أإآٱ', 'اااا'))      # توحيد الألف
    s = (s.replace('ة', 'ه')
          .replace('ى', 'ي')
          .replace('ؤ', 'و')
          .replace('ئ', 'ي'))
    s = s.translate(str.maketrans('٠١٢٣٤٥٦٧٨٩', '0123456789'))
    s = re.sub(r'[^\w\s\u0600-\u06FF]', ' ', s)         # رموز وإيموجي
    s = re.sub(r'\s+', ' ', s).strip().lower()
    return s
```

**حالات لازم تتعامل معاها:**

| الحالة | مثال | المعالجة |
|---|---|---|
| أجهزة | `Ahmed's iPhone` · `Galaxy S21` | إزالة اللاحقة |
| ألقاب | `م/ أحمد` · `Dr. Sara` · `المهندس` | إزالة |
| كنى | `أبو يوسف` · `أم محمد` | flag للمراجعة — صعبة |
| مسافات في الأسماء المركبة | `عبد الرحمن` vs `عبدالرحمن` | توحيد |
| ترتيب مختلف | `محمد أحمد علي` vs `علي محمد أحمد` | `token_set_ratio` |
| اسم أول فقط | `أحمد` | لو فيه أكتر من أحمد → review |

## ٢. Transliteration — عربي ↔ إنجليزي

نص الناس بتكتب بالإنجليزي: `Ahmed Mohamed` vs `أحمد محمد`

**الحل المقترح:** جدول تحويل + مطابقة صوتية

```python
# Ahmed / Ahmad / Ahmet → ahmd
# Mohamed / Mohammed / Muhammad / Mohamad → mhmd

```

جرّب مكتبات زي `camel-tools` أو ابنِ جدول للأسماء المصرية الشائعة
(٢٠٠ اسم بيغطوا ٩٠٪ من الحالات عمليًا).

## ٣. Fuzzy Layer

**استخدم `rapidfuzz`** — أسرع بكتير من `fuzzywuzzy`.

```python
from rapidfuzz import fuzz

# token_set_ratio بيتعامل مع اختلاف الترتيب والكلمات الزيادة
# "محمد أحمد علي" vs "أحمد علي محمد" → 100
score_set     = fuzz.token_set_ratio(a, b)
score_sort    = fuzz.token_sort_ratio(a, b)
score_partial = fuzz.partial_ratio(a, b)
```

**دمج مرجّح** — اضبط الأوزان عىل الـ test set بتاعك.

## ٤. ⭐ Ambiguity Detection — أهم قاعدة عندك

```python
best, second = top_two_matches

if best.score >= 0.88 and (best.score - second.score) >= 0.10:
    auto_match()
else:
    needs_review(suggestions=[best, second])
```

**ليه الفرق بين الأول والتاني أهم من السكور نفسه:**

لو في نفس البرنامج فيه `محمد علي` و `محمد علي حسن`، الاتنين هياخدوا سكور عالي
عىل مدخل `محمد علي`. السكور العالي مش دليل — **الفرق الصغير بين المرشحين = خطر**.

## ٧. Test Set — إلزامي

**ابنِ ١٠٠+ حالة حقيقية من بيانات حاتم** (مموّهة) وقيس:

```
Precision (الأهم) = من اللي طابقته، كام صح؟   ← الهدف: ١٠٠٪
Recall            = من اللي المفروض يتطابق، كام طابقته؟  ← الهدف: ≥٩٠٪
Review rate       = كام حالة راحت للمراجعة؟  ← الهدف: ≤١٠٪
```

**شغّل الاختبارات في CI.** أي تعديل يقلل الـ precision = رفض.

# المرحلة ٢ (أسبوع ٨–١٢) — Intent Parser

## العقد

```http
POST /parse
```

**Request:**
```json
{
  "text": "اقفل سيشن رياكت",
  "context": {
    "active_programs": [{"id": 3, "name": "React"}],
    "recent_sessions": [{"id": 412, "program_id": 3, "date": "2026-08-17"}]
  }
}
```

**Response:**
```json
{
  "intent": "close_session",
  "entities": {"program_id": 3, "session_id": 412},
  "confidence": 0.94,
  "clarification_needed": null
}
```

**لو فيه غموض:**
```json
{
  "confidence": 0.71,
  "clarification_needed": {
    "question": "فيه ٣ جلسات React لسه مقفلتش — أنهي واحدة؟",
    "options": [
      {"session_id": 410, "label": "الأحد ١٠ أغسطس"},
      {"session_id": 412, "label": "الثلاثاء ١٢ أغسطس"}
    ]
  }
}
```

## المبادئ

**١. Structured output إجباري.** استخدم tool calling / JSON schema صارم.
النموذج بيرجّع JSON منظم — **الكود هو اللي ينفذ، مش النموذج**.

**٢. سؤال واحد شامل.** لو فيه غموض، اسأل سؤال واحد يجمع كل الناقص —
مش ٥ أسئلة صغيرة. (دي قاعدة أصلية في تصميم المنتج.)

**٣. العامية المصرية.** الأوامر هتيجي كده:
`اقفل` · `نفّذ` · `دوّر` · `جهّز` · `ابعت` · `شوفلي` · `اعملي`
ابنِ أمثلة كتير في الـ prompt.

**٤. Validation طبقة تانية.** لو النموذج رجّع `session_id` مش موجود في الـ context،
ارفضه. متثقش في المخرجات بشكل أعمى.

**Intents المدعومة:**
`close_session` · `send_reminders` · `daily_brief` · `search` · `unknown`

# المرحلة ٣ (أسبوع ١٣–١٧) — Priority Engine

منطق "أهم ٣ أولويات النهاردة".

```python
POST /prioritize
{"items": [...]}  →  {"ranked": [...], "top_3": [...], "reasoning": "..."}
```

**عوامل الترتيب:**
| العامل | الوزن التقريبي |
|---|---|
| قرب الـ deadline | عالي |
| عدد الأشخاص المتأثرين | عالي |
| هل بيبلوك حاجة تانية | عالي |
| عمر البند (قد إيه معلّق) | متوسط |
| نوع البند (قرار vs مهمة) | متوسط |

**شرط أساسي:** الترتيب لازم يكون **قابل للشرح**. حاتم لازم يفهم ليه البند ده
جه الأول. متخليهوش صندوق أسود.

## تحذيرات

1. **متبنيش نموذج ML من الصفر.** كل ده يتحل بـ rules + fuzzy + embeddings جاهزة.
2. **خدمتك stateless.** كل المعرفة بتيجي في الـ request. مفيش DB عندك.
3. **الـ false positive هو العدو.** لما تشك، ارجع `needs_review`.
4. **لو خلصت المطابقة بدري** (أسبوع ٤ مثلًا)، ابدأ الـ intent layer فورًا —
   متقعدش مستني.
